`cart.test.js`를 추가했고, `node --test`(또는 `npm test`)로 테스트 9개가 모두 통과합니다. `cart.js`와 `package.json`은 고치지 않았고, 새 의존성이나 테스트 헬퍼도 없습니다.

**테스트한 동작**
- 합계: 빈 장바구니는 0, 여러 상품은 가격 x 수량의 합
- 담기: 수량 생략 시 1개, 같은 상품을 다시 담으면 수량 누적
- 수량 검증: 0과 음수는 `RangeError`, 실패해도 이미 담긴 수량은 그대로
- 제거: 있는 상품은 합계에서 빠지고 `true`, 없는 상품은 `false`에 합계 변화 없음

**검증:** 임시 복사본의 `cart.js`에 버그 7가지를 넣어 봤고(`<=`를 `<`로 변경, 검증 삭제, 누적 제거 등), 모두 해당 테스트가 실패했습니다.

**확인이 필요한 동작**

스펙 문서가 없어서 코드만으로는 의도를 판단할 수 없는 동작들입니다. 버그를 정상 동작으로 고정하지 않도록 테스트에는 넣지 않았습니다. 아래 결과는 직접 실행해 확인했습니다.

| 입력 | 현재 결과 | 문제 |
|---|---|---|
| 같은 상품을 다른 가격으로 다시 담기: `add('a', 1000, 2)` 후 `add('a', 2000, 1)` | 합계 3000 | 두 번째 가격이 말없이 무시됨 |
| 수량 `NaN`: `add('a', 1000, NaN)` | 예외 없이 합계 `NaN` | `NaN <= 0`이 거짓이라 검증을 통과하고, 장바구니 전체 합계가 깨짐 |
| 문자열 수량: `add('a', 1000, '2')` 후 `add('a', 1000, '3')` | 합계 23000 | 수량이 `'23'`으로 이어 붙음 |
| 가격 누락: `add('a')` | 합계 `NaN` | 가격 검증이 없음 |
| 음수 가격: `add('a', -1000)` | 합계 -1000 | 가격 검증이 없음 |
| 소수 수량: `add('a', 1000, 1.5)` | 합계 1500 | 정수 수량만 받아야 한다면 막아야 함 |
| 소수 가격: `add('a', 0.1, 3)` | 합계 0.30000000000000004 | 가격이 소수일 수 있다면 정수 단위로 다뤄야 함 |

이 중 `NaN`, 문자열 수량, 가격 누락은 금액이 틀어지는 경우라 먼저 보시길 권합니다. 의도한 규칙을 알려 주시면 그에 맞춰 테스트를 추가하겠습니다.
