`src/order_validator.py` 테스트를 `tests/test_order_validator.py`에 작성했고, 14개 모두 통과합니다.

    python -m unittest discover -t . -s tests

pytest가 설치되어 있지 않아 표준 `unittest`로 작성했습니다.

**필드가 많은 문제:** `make_order(**overrides)` 헬퍼 하나로 해결했습니다. 정상 주문을 기본값으로 만들고, 각 테스트는 검증할 필드만 넘깁니다. 예: `make_order(unit_price=-1)`

**다룬 범위**
- 정상 주문은 에러 없음
- 6개 규칙의 통과/실패 경계값: 수량 0·1·99·100, 가격 -1·0, 우편번호 4·5·6자리와 숫자 아닌 문자, 배송일 전날·당일·다음날, 결제수단 대소문자 등
- 여러 규칙을 동시에 어기면 모든 에러가 검사 순서대로 나옴

실패 케이스는 에러 목록 전체를 비교하므로, 엉뚱한 에러가 같이 나와도 잡힙니다. 비교 연산자와 조건을 일부러 바꾼 16가지 변형을 임시 복사본에 적용해 봤고, 모두 테스트가 실패로 잡아냈습니다. `src/`는 수정하지 않았습니다.

**확인이 필요한 동작** (의도된 동작인지 몰라서 테스트로 고정하지 않았습니다)
- 이메일은 `@` 포함 여부만 봐서 `"@"` 한 글자도 통과합니다.
- 우편번호에 `str.isdigit()`를 써서 비ASCII 숫자도 통과합니다.
- `order_id`, `shipping_name` 등 나머지 필드는 검증하지 않아 빈 문자열도 통과합니다.
