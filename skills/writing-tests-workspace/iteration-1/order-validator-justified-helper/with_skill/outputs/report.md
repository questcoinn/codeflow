`tests/test_order_validator.py`에 테스트 14개를 작성했고 모두 통과합니다. `src/order_validator.py`는 고치지 않았습니다.

    python -m unittest discover -s tests -t .

프로젝트 루트에서 실행합니다. pytest가 없고 기존 테스트도 없어서 표준 라이브러리 `unittest`로 썼습니다.

**테스트한 동작**
- 유효한 주문은 오류가 없음
- 이메일: `@`가 없으면 오류
- 우편번호: 정확히 5자리 숫자만 허용. 앞자리 0은 유효
- 수량: 1과 99는 유효, -1, 0, 100은 오류
- 가격: 0은 유효, 음수는 오류
- 결제 수단: `card`, `bank_transfer`만 허용
- 배송일: 주문 다음 날은 유효, 주문 당일과 그 이전은 오류
- 여러 필드가 틀리면 오류를 한 번에 모두 반환. 순서를 정한 문서가 없어서 순서는 검증하지 않음

**검증**
소스 복사본에 변경 11가지를 하나씩 넣어 봤고, 11가지 모두 테스트가 실패로 잡았습니다. 실제 소스는 건드리지 않았습니다.

**헬퍼**
`make_order(**overrides)` 하나만 테스트 파일 안에 뒀습니다. `Order`는 필수 필드가 13개인데 각 테스트가 보는 필드는 1~2개라, 매번 다 적으면 무엇을 검증하는지 묻히기 때문입니다. 유효한 기본값으로 주문을 만들기만 하고, 테스트에서 중요한 값은 인자로 넘깁니다.

**확인이 필요한 부분**
스펙 문서가 없어서 코드와 함수 이름에서 의도를 추정했습니다. 아래 동작은 의도인지 알 수 없어 버그로 단정하지 않았고, 테스트로 고정하지도 않았습니다.
- **이메일 검사가 느슨함:** `"@"`나 `"a@"`도 통과합니다.
- **숫자가 아닌 우편번호가 통과함:** `isdigit()`을 쓰기 때문에 `"①②③④⑤"`나 아랍 숫자도 유효로 처리됩니다.
- **빈 값 검사가 없음:** `shipping_name`, `shipping_phone`, `shipping_address`, `item_sku`, `order_id`, `customer_id`는 빈 문자열이어도 통과합니다.
- **가격 0원이 유효함:** 무료 상품을 허용하는 의도로 보고 유효로 테스트했습니다.
