# 명확한 한국어 글쓰기
 
## 왜 이 스킬이 필요한가
 
AI가 쓴 글이 읽기 피곤한 이유는 대개 내용이 틀려서가 아니라 **문장이 불명확해서**다. 단어는 다 아는데 누가 무엇을 했는지, 그래서 요점이 무엇인지 다시 읽어야 알 수 있다. 가볍게 넘길 수 있는 글이면 상관없지만, PR 설명이나 업무 메시지처럼 반드시 읽어야 하는 글에서는 독자가 복잡한 내용과 흐린 문장을 동시에 해독해야 한다.
 
명확한 글은 독자에 대한 책임이다. 목표는 "AI 티를 지우는 것"이 아니다. 특정 단어나 기호를 피한다고 글이 명확해지지 않는다. 목표는 **독자가 한 번 읽고 누가 무엇을 했는지, 요점이 무엇인지 아는 것**이다. "AI가 쓴 것 같다"는 요청을 받으면 말투를 흉내 내지 말고 아래 세 결함을 찾아 고친다.
 
이 기준은 좋은 글의 필요조건이다. 세 결함이 없다고 좋은 글이 되지는 않지만, 결함이 있으면 좋은 글이 될 수 없다.
 
## 세 가지 결함
 
아래 표의 "명확한 문장"에 나오는 이름, 수치, 날짜는 글쓴이가 알려 준 정보라고 가정한 예시다. 실제 작업에서 원문에 없는 정보가 필요하면 지어내지 말고 `[담당자?]`, `[수치?]`처럼 표시한다.
 
### 결함 1. 행위자와 행동을 숨긴다
 
문장에는 두 층위가 있다.
- 이야기 층위: 누가(행위자) 무엇을 하는가(행동)
- 문법 층위: 주어와 서술어
**행위자를 주어에, 행동을 서술어(동사)에 둘 때 가장 명확하다.** 행동을 명사로 바꾸고(명사화) 행위자를 빼면, 독자는 "그래서 누가 했다는 거지?"를 스스로 복원해야 한다.
 
한국어에서 자주 보이는 형태:
- 명사화 + 빈 동사: "~의 진행", "~이 이루어지다", "~을 수행하다", "~을 실시하다", "~에 대한 검토가 필요하다"
- 행위자 없는 피동: "~되었다", "~되어지다", "~하게 되었다", "~에 의해 ~되었다"
- 사물이 주어인 문장: "이번 변경은 성능 향상을 가져왔다"
| 흐린 문장 | 명확한 문장 |
|---|---|
| 캐시 무효화 로직에 대한 수정이 이루어졌습니다. | 캐시 무효화 로직을 고쳤습니다. |
| 배포 전 QA팀에 의한 검증이 진행될 예정입니다. | QA팀이 배포 전에 검증합니다. |
| 해당 이슈에 대한 원인 파악이 필요한 상황입니다. | 이 이슈의 원인을 아직 모릅니다. 민수 님이 내일까지 확인하겠습니다. |
 
**절대 규칙은 아니다.** 행위자가 중요하지 않거나 알 수 없을 때, 또는 독자가 주목해야 할 대상을 일부러 앞에 둘 때는 피동이나 사물 주어가 낫다. ("서버가 새벽 3시에 재시작되었다" — 누가 재시작했는지보다 재시작 사실이 중요할 때.) 판단 기준은 "독자가 행위자를 알아야 하는가"다.
 
**한국어는 주어를 생략해도 자연스럽다.** 주어가 없다는 것 자체는 결함이 아니다. 문맥상 행위자가 분명하면 생략한 채로 둔다. 독자가 "누가 했지?"를 되물을 문장에서만 행위자를 쓴다. 모든 문장에 주어를 채우면 오히려 번역투가 되어 읽기 어렵다.
 
### 결함 2. 모호한 표현
 
단어마다 뜻은 분명한데 무엇을 가리키는지 흐린 경우다. AI가 쓴 글에서 가장 흔한 결함이다.
 
- **불분명한 지시어**: "이", "이것", "해당", "위의", "앞서 언급한" — 가리키는 대상이 둘 이상이거나 멀리 떨어져 있으면 대상을 다시 쓴다.
- **명사 연쇄**: "사용자 세션 진입 경계 검증 로직", "데이터 처리 파이프라인 안정성 확보 방안". 명사 서너 개가 붙으면 독자는 관계를 추측해야 한다. 조사와 동사를 넣어 풀어 쓴다. 한자어와 복합어가 이어질 때 특히 자주 생긴다.
- **이상한 단어 조합**: 사람이 실제로 쓰지 않는 이름을 붙이는 것. 레모네이드 가판대를 "음료 소매 사업체"라고 부르는 식이다. 독자와 동료가 그 대상을 실제로 부르는 이름을 쓴다. 코드라면 실제 함수·파일·화면 이름을 쓴다.
- **과한 추상어**: "개선", "최적화", "고도화", "효율화", "관련 처리" — 무엇을 어떻게 바꿨는지 구체적으로 쓴다.
- **번역투**: "~를 통해", "~에 있어서", "~함에 있어", "~를 가지다", "~에 대해", "~적(的)" 남용. 한국어로 자연스럽게 말하는 방식으로 바꾼다.
| 흐린 문장 | 명확한 문장 |
|---|---|
| DB 준비 상태 확인은 인증 핸들러 실행 전, 사용자 세션 진입 경계에 위치합니다. | 로그인 요청이 들어오면 인증 처리 전에 DB가 준비됐는지 먼저 확인합니다. |
| 해당 부분 고도화를 통해 사용자 경험의 개선을 도모했습니다. | 검색 결과가 뜨는 시간을 2초에서 0.5초로 줄였습니다. |
| 이를 위해 이것을 먼저 처리했습니다. | 마이그레이션이 실패하지 않도록 오래된 컬럼을 먼저 지웠습니다. |
 
### 결함 3. 알맹이 없는 문장과 잘못된 강조
 
단어도 문법도 이해되는데 요점을 찾는 데 시간이 걸리는 문장이다. 핵심이 부가 정보 뒤에 묻혀 있거나, 아무 정보도 없는 문장이 끼어 있다.
 
한국어는 서술어가 문장 끝에 오기 때문에 이 결함에 특히 취약하다. 조건·이유·배경을 앞에 길게 늘어놓으면 독자는 마지막 어절까지 읽어야 "그래서 뭘 한다는 건지" 안다.
 
- **핵심을 앞에 둔다.** 문단의 첫 문장, 문장의 앞부분에 결론·요청·결정을 쓴다. 이유와 배경은 그 뒤에 붙인다.
- **긴 문장은 나눈다.** "~하고, ~이며, ~하기 때문에, ~하므로" 식으로 이어지면 끊는다. 한 문장에 한 가지 요점.
- **알맹이 없는 문장을 지운다.** "~하는 것이 중요합니다", "~라고 할 수 있습니다", "다양한 측면에서 살펴보았습니다", "결론적으로 말씀드리면" 같은 문장은 지워도 정보가 줄지 않는다.
- **얼버무림을 줄인다.** "~인 것으로 보입니다", "~일 수도 있을 것 같습니다"는 정말 불확실할 때만 쓰고, 불확실하면 무엇이 불확실한지 쓴다.
| 흐린 문장 | 명확한 문장 |
|---|---|
| 현재 다른 작업은 결과에 의존하지 않으므로, 폴링 결과가 반환되는 즉시 내용을 정리해서 공유드리도록 하겠습니다. | 폴링이 끝나면 결과를 공유하겠습니다. (지금 기다리는 다른 작업은 없습니다.) |
| 여러 가지 요인을 종합적으로 검토한 결과, 기존 방식을 유지하는 것이 바람직하다는 판단에 이르게 되었습니다. | 기존 방식을 유지하겠습니다. 새 방식은 메모리를 두 배로 쓰는데 속도 이득이 5%뿐이었습니다. |
 
강조를 바로잡은 뒤에 남는 부가 문장을 둘지 말지는 문체 선택이다. 핵심이 앞에 있으면 어느 쪽이든 괜찮다.
 
## 작업 방식
 
### 새 문서를 쓸 때
 
1. **독자와 요점을 먼저 정한다.** 누가 읽는가, 읽고 나서 무엇을 알거나 해야 하는가를 한 문장으로 정리한다. 이 문장이 글의 첫 문장이 되는 경우가 많다.
2. **결론 → 근거 → 세부 순서로 쓴다.** 독자가 첫 문단만 읽고 멈춰도 요점을 가져가게 한다.
3. **구체적으로 쓴다.** 행위자(누가), 대상(실제 이름), 수치, 날짜, 다음 행동을 넣는다. 모르는 정보는 지어내지 말고 `[수치?]`처럼 표시한다.
4. **아래 자체 점검을 한 번 돈다.**
문서 종류별 첫 문장 예시:
- PR 설명: 이 PR이 무엇을 바꾸는지와 왜 바꾸는지.
- 장애 보고: 무엇이 언제부터 언제까지 안 됐고, 지금 상태가 어떤지.
- 요청 메시지: 무엇을 언제까지 해 달라는지.
- 결정 공유: 무엇으로 정했는지.
### 기존 글을 퇴고할 때
 
1. 글 전체를 읽고 글쓴이가 전하려는 요점을 한 문장으로 파악한다. 요점이 글에 없거나 뒤에 묻혀 있으면 그것부터 고친다.
2. 문장마다 세 결함을 확인하고 고친다. 글쓴이가 쓴 사실과 의도는 바꾸지 않는다. 원문에 없는 정보가 필요하면 지어내지 말고 `[담당자?]`, `[수치?]`처럼 표시해 확인을 요청한다.
3. 원래 문체(존댓말 수준, 격식, 말투)는 유지한다.
4. 결과는 다음 형식으로 준다.
   - 고친 글 전체
   - 주요 수정 사항 3~5개: 어떤 결함이었고 어떻게 고쳤는지 한 줄씩. 사소한 수정은 하나하나 나열하지 않는다.
사용자가 "고쳐줘" 없이 "검토해줘", "피드백 줘"라고만 하면 고친 글 대신 결함이 있는 문장과 수정 제안을 준다.
 
## 자체 점검
 
글을 넘기기 전에 다음을 확인한다.
 
- [ ] 첫 문장(또는 첫 문단)에 요점이 있는가?
- [ ] 독자가 "누가 했지?"를 되물을 문장에서 행위자가 보이는가? (문맥상 분명한 주어를 억지로 채우지는 않았는가?)
- [ ] "이", "해당", "위의"가 가리키는 대상이 하나로 분명한가?
- [ ] 명사가 셋 이상 붙은 덩어리는 없는가?
- [ ] 동료가 실제로 부르는 이름을 썼는가?
- [ ] "개선", "고도화", "관련 처리" 같은 추상어를 구체적인 변화로 바꿨는가?
- [ ] "~를 통해", "~에 있어서" 같은 번역투가 남아 있지 않은가?
- [ ] 지워도 정보가 줄지 않는 문장은 없는가?
- [ ] 정말 불확실한 내용만 얼버무렸고, 무엇이 불확실한지 썼는가?
- [ ] 한 문장에 요점이 두 개 이상 들어 있지 않은가?
- [ ] 원문에 없는 사실을 지어내지 않았는가?
더 많은 고쳐 쓰기 예시가 필요하면 `references/examples.md`를 읽는다.
