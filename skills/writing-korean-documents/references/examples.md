# 고쳐 쓰기 예시
 
문서 종류별로 세 결함이 함께 나타나는 예시와 고친 결과다. 문장 단위 예시는 SKILL.md에 있고, 여기서는 문단 단위로 보여준다.
 
각 예시의 "고친 후"에 나오는 이름, 수치, 날짜, 파일명은 글쓴이가 따로 알려 준 정보라고 가정한 값이다. 실제 퇴고에서 원문에 없는 정보가 필요하면 지어내지 말고 `[담당자?]`, `[수치?]`처럼 표시해 확인을 요청한다.
 
## 1. PR 설명
 
**고치기 전**
> 본 PR은 주문 처리 파이프라인의 안정성 확보를 위한 개선 작업을 포함하고 있습니다. 기존 구조에서는 외부 결제 API 응답 지연 상황 발생 시 타임아웃 처리 관련 이슈가 존재하였으며, 이에 대한 대응으로 재시도 로직의 도입 및 타임아웃 값의 조정이 이루어졌습니다. 또한 관련 테스트 코드의 보강도 함께 진행되었습니다.
 
**고친 후**
> 결제 API가 늦게 응답할 때 주문이 실패하던 문제를 고쳤습니다.
>
> - `PaymentClient`의 타임아웃을 3초에서 10초로 늘렸습니다.
> - 타임아웃이 나면 최대 2번 다시 시도합니다.
> - 지연 응답 상황을 재현하는 테스트를 `payment_client_test.go`에 추가했습니다.
 
**고친 점**
- 결함 3: 무엇을 고쳤는지가 셋째 줄에 묻혀 있었다 → 첫 문장으로 올렸다.
- 결함 2: "주문 처리 파이프라인의 안정성 확보", "관련 이슈" → 실제 증상과 실제 클래스 이름으로 바꿨다.
- 결함 1: "도입 및 조정이 이루어졌습니다", "보강도 진행되었습니다" → "늘렸습니다", "추가했습니다"로 행동을 동사로 썼다.
## 2. Slack 요청 메시지
 
**고치기 전**
> 안녕하세요! 다음 주 릴리스 일정과 관련하여 몇 가지 확인이 필요한 사항이 있어서 연락드립니다. 현재 디자인 시안의 최종 확정 여부에 따라 프론트엔드 작업 일정이 영향을 받을 수 있는 상황인데요, 혹시 시간 되실 때 확인 부탁드려도 될까요?
 
**고친 후**
> 지은 님, 결제 화면 디자인 시안을 수요일까지 확정해 주실 수 있을까요? 확정돼야 프론트 작업을 시작할 수 있고, 수요일을 넘기면 다음 주 릴리스에 못 들어갑니다.
 
**고친 점**
- 결함 3: 요청이 맨 끝에, 그것도 "확인 부탁"으로 흐리게 있었다 → 요청과 기한을 첫 문장에 썼다.
- 결함 2: "몇 가지 확인이 필요한 사항", "디자인 시안" → 어떤 화면의 시안인지, 무엇을 해 달라는지 구체적으로 썼다.
- 결함 1: "일정이 영향을 받을 수 있는 상황" → 누가 무엇을 못 하게 되는지 썼다.
## 3. 장애 보고
 
**고치기 전**
> 금일 오전 중 일부 사용자 대상 로그인 기능 장애가 발생하였으며, 원인 분석 결과 인증 서버 인증서 만료가 주요 원인인 것으로 파악되었습니다. 현재는 인증서 갱신 조치가 완료되어 정상화된 상태이며, 향후 재발 방지를 위한 모니터링 체계 고도화를 검토 중에 있습니다.
 
**고친 후**
> 오늘 오전 9:10~9:45, 안드로이드 앱 사용자가 로그인하지 못했습니다. 지금은 정상입니다.
>
> 원인: 인증 서버의 TLS 인증서가 9:10에 만료됐습니다. 9:45에 인프라팀이 인증서를 갱신했습니다.
>
> 재발 방지: 인증서 만료 14일 전에 #infra-alert 채널로 알림이 가도록 설정하겠습니다. (담당: 인프라팀, 금요일까지)
 
**고친 점**
- 결함 2: "금일 오전 중", "일부 사용자" → 정확한 시간대와 영향받은 사용자로 바꿨다.
- 결함 1: "갱신 조치가 완료되어" → 누가 언제 갱신했는지 썼다.
- 결함 3, 결함 2: "모니터링 체계 고도화를 검토 중" → 실제로 무엇을, 누가, 언제까지 할지 썼다. 정해진 게 없다면 "아직 정하지 않았습니다"라고 쓰는 편이 낫다.
## 4. 작업 결과 보고 (AI 에이전트 응답 스타일)
 
**고치기 전**
> 이번 세션에서 확정된 것은, 기존 설계 접근이 이 GPU에 근본적으로 부적합하다는 점이며, 이로써 각 변경 사항의 효과를 개별적으로 귀속할 수 있는 통제된 기준선이 확보되었습니다.
 
**고친 후**
> 기존 설계는 이 GPU에 맞지 않습니다. 이제 새 설계를 기준으로 삼아, 옵션을 하나씩 바꿔 보며 각 변경이 얼마나 영향을 주는지 따로 잴 수 있습니다.
 
**고친 점**
- 결함 1: "부적합하다는 점이며", "기준선이 확보되었습니다" → 무엇이 맞지 않는지, 이제 무엇을 할 수 있는지 동사로 썼다.
- 결함 2: "효과를 개별적으로 귀속", "통제된 기준선" → 실제로 하는 일(하나씩 바꿔 보며 잰다)로 풀었다.
- 원문에 없는 사실(느려졌다는 내용 등)은 더하지 않았다.
